### SWHR2-R-0027 · Framework sample application idle session expiry

#### SWHR2-R-0027.01 · Visitor idle for 31 minutes

  - Preconditions: The framework sample application with a fake clock. Visitor session S1 holds a server-side value (e.g. a stored marker "m1").

### SWHR2-R-0029 · Separate administrator and supplier areas

#### SWHR2-R-0029.01 · User moves from the administrator area to the supplier area
- **SWHR2-C-0255** (e2e, approved, v1) Moving from the administrator area to the supplier area means signing out of admin and signing in to supplier
  - Preconditions: Admin user signed in to the administrator area. Supplier credentials are available.

### SWHR2-R-0030 · Administrator signs out before using the supplier area

#### SWHR2-R-0030.01 · Administrator still signed in
- **SWHR2-C-0256** (e2e, approved, v1) A user still signed in as administrator cannot use the supplier area until signing out
  - Preconditions: User signed in to the administrator application.
  - Step 1: Without signing out, open the supplier application and try a supplier action (e.g. Display Inventory).
  - Step 2: Sign out of admin and try again after signing in as supplier.
  - Expected: While still signed in as admin, the supplier action is refused (sign-in prompt or access denied). It succeeds only after signing out of admin and signing in as supplier.

  - Step 2: Read what the spy queue received.

#### SWHR2-R-0121.02 · Caller outside the application

  - Preconditions: The server is running.

  - Step 2: Check whether any of them reach the hand-off service.
  - Expected: No public route reaches the hand-off service (a request to its likely paths returns 404). It can only be called from inside the server code.
