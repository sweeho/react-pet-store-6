### SWHR2-R-0288 · Landing page

#### SWHR2-R-0288.01 · A user opens the root route
- **SWHR2-C-0270** (e2e, approved, v1) Root URL shows the landing page
  - Preconditions: App server running; no prior navigation in the browser session.
  - Step 1: Open the application's root URL (/) in the browser
  - Step 2: Wait for the page to finish loading
  - Expected: The landing page is displayed (its main heading is visible) and the URL remains /, with no redirect to another route and no not-found page.
- **SWHR2-C-0271** (unit, approved, v1) Landing page links to every primary area
  - Preconditions: The list of primary application areas is defined in the app's navigation/area config.
  - Step 1: Render the landing page component inside a router
  - Step 2: Collect every link in the landing page content
  - Step 3: Compare the link targets with the configured list of primary areas
  - Expected: Every configured primary area has exactly one link on the landing page whose href matches that area's route; no primary area is missing.
- **SWHR2-C-0272** (e2e, approved, v1) Each landing page link opens its area
  - Preconditions: App server running.
  - Step 1: Open /
  - Step 2: For each primary-area link on the landing page, click it
  - Step 3: Check the resulting page, then go back to /
  - Expected: Each click navigates to that area's route and renders its page (not the not-found page).

### SWHR2-R-0291 · Shared state frames

#### SWHR2-R-0291.01 · A page has nothing to show
- **SWHR2-C-0277** (unit, approved, v1) Page with no data renders the shared empty frame
  - Preconditions: A data-driven page (e.g. the users list) whose data source is mocked to return an empty list.
  - Step 1: Mock the page's data fetch to resolve with no items
  - Step 2: Render the page
  - Step 3: Wait for loading to finish
  - Expected: The shared empty-state frame is rendered (identified by its shared test id/role and empty-state message) and no list items or error frame are shown.

#### SWHR2-R-0291.02 · A page fails to load
- **SWHR2-C-0278** (unit, approved, v1) Page whose data fails renders the shared error frame
  - Preconditions: A data-driven page (e.g. the users list) whose data fetch is mocked to reject or return HTTP 500.
  - Step 1: Mock the page's data fetch to fail
  - Step 2: Render the page
  - Step 3: Wait for loading to finish
  - Expected: The shared error frame is rendered with an error message and a visible Retry button; the empty frame and data content are not shown.
- **SWHR2-C-0279** (unit, approved, v1) Retry in the error frame reloads the data
  - Preconditions: Data fetch mocked to fail on the first call and succeed with one item on the second.
  - Step 1: Render the page and wait for the error frame
  - Step 2: Click the Retry button
  - Step 3: Wait for loading to finish
  - Expected: The fetch is called a second time, the error frame disappears and the returned item is displayed.
