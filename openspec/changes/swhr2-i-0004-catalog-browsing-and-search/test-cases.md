## catalog-browsing

### SWHR2-R-0001 · Catalog keyword search

#### SWHR2-R-0001.01 · Any keyword matches
- **SWHR2-C-0178** (integration, approved, v1) Searching "angel koi" in en_US returns both the Angelfish item and the item whose description mentions koi
  - Preconditions: en_US catalog with item EST-1 (product name "Angelfish") and item EST-4 (description contains "koi"; product name has neither word).
  - Step 1: Run a catalog search for "angel koi" in en_US.
  - Expected: The results include both EST-1 and EST-4.

#### SWHR2-R-0001.02 · Category id matches
- **SWHR2-C-0179** (integration, approved, v1) Searching "fish" returns an item through its category id FISH even if no text matches
  - Preconditions: Item EST-4 belongs to a product in category FISH. Neither its product name nor its description contains "fish" (e.g. product "Koi").
  - Step 1: Run a catalog search for "fish" in en_US.
  - Expected: EST-4 is in the results.

#### SWHR2-R-0001.03 · Duplicate keywords
- **SWHR2-C-0180** (unit, approved, v1) Search text "fish fish koi" searches for the two distinct keywords fish and koi
  - Preconditions: The search function with a spy on the catalog query.
  - Step 1: Run a search for "fish fish koi".
  - Step 2: Read the keywords passed to the catalog query.
  - Expected: The query receives exactly ["fish", "koi"], with no duplicates.

#### SWHR2-R-0001.04 · Mixed-case keyword
- **SWHR2-C-0181** (integration, approved, v1) Searching "Dog" in mixed case in en_US returns the Bulldog item
  - Preconditions: en_US item EST-6 with product name "Bulldog".
  - Step 1: Run a catalog search for "Dog" in en_US.
  - Expected: EST-6 is in the results.

#### SWHR2-R-0001.05 · Blank search text
- **SWHR2-C-0182** (unit, approved, v1) Empty or whitespace-only search text returns an empty result without querying the catalog
  - Preconditions: The search function with a spy on the catalog query.
  - Step 1: Run a search with "".
  - Step 2: Run a search with "   ".
  - Expected: Both return an empty result, and the catalog query spy is never called.

### SWHR2-R-0002 · Catalog read paths and failure reporting

#### SWHR2-R-0002.01 · Both read paths agree
- **SWHR2-C-0183** (integration, approved, v1) Reading FISH products directly and through the catalog service gives the same products and details
  - Preconditions: Category FISH with en_US products Angelfish and Koi.
  - Step 1: Read FISH products in en_US through the direct web-tier read path.
  - Step 2: Read FISH products in en_US through the catalog service path.
  - Step 3: Compare the two results.
  - Expected: Both results hold the same products (Angelfish and Koi) with the same id, name and description, in the same order.

#### SWHR2-R-0002.02 · Data access selected by configuration
- **SWHR2-C-0280** (integration, approved, v1) Catalog reads go through the data-access implementation named in the deployment configuration
  - Preconditions: Two catalog data-access implementations are registered (the default one and a recording test double). The deployment configuration names the recording test double as the catalog data-access implementation. Category "FISH" exists with en_US product "Angelfish".
  - Step 1: Load the deployment configuration naming the recording test double
  - Step 2: Read the products of category "FISH" in en_US through the catalog service
  - Step 3: Inspect which data-access implementation received the read
  - Expected: The recording test double named in the configuration received the "FISH" products read, and the default implementation received no call.
- **SWHR2-C-0281** (integration, approved, v1) Catalog reads use the database dialect named in the deployment configuration
  - Preconditions: The deployment configuration names the SQLite dialect for the catalog store. Category "FISH" exists with en_US products "Angelfish" and "Koi" in a SQLite catalog store.
  - Step 1: Load the deployment configuration naming the SQLite dialect
  - Step 2: Read the products of category "FISH" in en_US through the catalog service
  - Step 3: Inspect the dialect of the database connection that served the read
  - Expected: The read was served by a SQLite connection and returned "Angelfish" and "Koi".
- **SWHR2-C-0282** (integration, approved, v1) Changing only the configured data-access implementation changes which implementation serves catalog reads
  - Preconditions: Two recording catalog data-access implementations, A and B, are registered. Category "FISH" exists with en_US product "Angelfish".
  - Step 1: Start the catalog with the deployment configuration naming implementation A and read the products of "FISH" in en_US
  - Step 2: Start the catalog again with the same configuration except it names implementation B, and read the products of "FISH" in en_US
  - Step 3: Inspect which implementation served each read
  - Expected: The first read was served only by A and the second only by B, with no code change between the two runs.

#### SWHR2-R-0002.03 · Catalog store unreachable
- **SWHR2-C-0185** (integration, approved, v1) An unreachable catalog store reports a catalog failure, not an empty list
  - Preconditions: The catalog datastore connection is made to fail (e.g. the db file is unreadable or the client is stubbed to throw).
  - Step 1: Request the product list for FISH.
  - Expected: A catalog failure is raised or returned (an error response through the API). No empty or partial list is returned.

### SWHR2-R-0036 · Shared five-minute cache of catalog pages

#### SWHR2-R-0036.01 · Change appears within five minutes
- **SWHR2-C-0188** (integration, approved, v1) A product added to FISH appears in its product list 6 minutes later
  - Preconditions: The FISH product list has been viewed once, so it is cached. The clock can be faked.
  - Step 1: Add a new product "Goldfish" to FISH.
  - Step 2: Move the fake clock forward 6 minutes.
  - Step 3: Request the FISH product list as a different shopper.
  - Expected: The list includes "Goldfish".

#### SWHR2-R-0036.02 · Cached copy reused across shoppers
- **SWHR2-C-0189** (integration, approved, v1) Within 5 minutes, shopper B may be served the FISH list cached from shopper A's view
  - Preconditions: Shopper A viewed the FISH list at T0. The clock can be faked.
  - Step 1: At T0 + 1 minute, rename a FISH product from "Koi" to "Koi Carp".
  - Step 2: As shopper B (a different session), request the FISH list.
  - Step 3: Check whether the page was served from the shared cache.
  - Expected: The request succeeds. B is served either A's cached render (still showing "Koi") or a fresh render ("Koi Carp"), and nothing else. The test passes in both cases and fails only if the list is wrong or the request errors.

#### SWHR2-R-0036.03 · Item detail not cached
- **SWHR2-C-0190** (integration, approved, v1) An item's detail page shows a new unit price immediately (not cached)
  - Preconditions: The EST-1 detail page has just been viewed and showed unit price 10.00.
  - Step 1: Change EST-1's unit price to 12.00.
  - Step 2: Request the EST-1 detail page again straight away.
  - Expected: The page shows 12.00.
